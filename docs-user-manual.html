01What CliniOps does

CliniOps sits on top of the data you already have — databases, spreadsheets, reports and documents — and lets you interrogate it in plain language. You ask a question the way you would ask a colleague; CliniOps works out how to answer it, runs the query, and explains the result.

Everything in the product follows one sequence:

  1. Connect your data. Link a database, or upload files. Nothing is copied out of your systems that you have not chosen to share.
  2. Create an agent. An agent is pointed at a specific slice of that data and given instructions on how to answer questions about it.
  3. Ask questions. Type a question; get an answer in prose, with the option to see the query behind it.
  4. Build dashboards. Save the questions worth watching as widgets and arrange them on a dashboard.

Each step builds on the one before it. You cannot create an agent before connecting data, and you cannot build a dashboard before you have an agent. The Help & Setup page tracks how far along you are.

Who does what

Everyone in your organisation can connect data, create agents, ask questions and build dashboards. Only organisation admins can invite colleagues and change their roles.

02Getting started

If you were invited by a colleague

  1. Open the invitation email. It contains your email address and a temporary password.
  2. Go to the CliniOps sign-in page and enter both.
  3. You will receive a one-time code by email. Enter it to confirm your identity.
  4. Choose a permanent password. You will land in the application.
Temporary passwords expire

The one-time code is valid for five minutes. If it lapses, sign in again with the temporary password to be sent a fresh one.

If you are signing up yourself

  1. Choose Sign up and enter your work email address.
  2. Enter the verification code sent to that address, and set a password.
  3. Complete organisation setup: your organisation's name, time zone, industry, team size, and your own job title. Choose Organisation admin if you will be the one inviting colleagues.

Your first visit

The first time you reach the home page, a short guided tour highlights each part of the interface and walks through the four steps above. It takes about a minute. You can leave it at any point with Skip tour, and replay it later from Help & Setup → Replay tour.

Signing in afterwards

Sign in with your email address and password. You will be taken straight to your home page. If you follow a link to a page while signed out, CliniOps returns you to that page once you have signed in.

04Connect your data

Open Data Management. There are two ways to bring data in: connect to a live database, or upload files.

4.1  Connecting a database

Choose Add Data Source, pick the type, give the connection a memorable name, and fill in the details.

TypeWhat you need
PostgreSQLHost, port (5432), database name, username, password
MySQLHost, port (3306), database name, username, password
SQL ServerHost, port (1433), database name, username, password
SnowflakeAccount, warehouse, database, schema, username, password
AWS RDSEngine (PostgreSQL, MySQL, MariaDB or SQL Server), endpoint, port, database, master username and password
Azure SQLServer name, port (1433), database, username, password
SQLiteFull path to the database file
Amazon S3Access key, secret key, region, bucket, and an optional folder prefix

Use Test Connection before saving. If it cannot connect, CliniOps tells you why in plain terms — wrong password, host unreachable, no such database — rather than showing a technical error.

For AWS RDS and Azure SQL

These usually fail for network reasons rather than credentials. The instance must accept connections from wherever CliniOps is running: check the RDS security group, or add the server's IP address to the Azure SQL firewall rules.

4.2  Uploading spreadsheets

CSV and Excel files become tables you can query. A new table needs a metadata file first, describing what its columns mean — this is what allows an agent to interpret your data correctly.

  1. Choose Upload Data and select Structured.
  2. Choose New table, and give it a name.
  3. Download the metadata template from the dialog. It has three columns:
    • column_name — exactly as it appears in your data file
    • data_type — text, number, date, and so on
    • description — what the column means in your business
  4. Fill in the template, attach it, attach your data file, and upload.

To add more data to a table later, choose Existing table and pick it from the list. The columns must match the ones already defined; if they do not, the upload is rejected and the mismatch is listed.

Bulk uploads

You can upload several files at once, or a single .zip containing them. Each file is processed separately and reported on individually, so one bad file will not stop the rest.

4.3  Uploading documents

PDF, Word, PowerPoint, text, Markdown and HTML files are handled differently: rather than becoming tables, they are read, split into passages and indexed so an agent can find and quote the relevant parts. Choose Unstructured when uploading these.

This is the right choice for protocols, reports, contracts, meeting notes — anything written rather than tabulated.

4.4  Importing from Amazon S3

An S3 bucket holds files rather than tables, so it is used as a source to import from rather than something you query directly.

  1. Save the S3 connection as in 4.1.
  2. Click Browse on its row in the connections table.
  3. The bucket's CSV, Excel and JSON files are listed with their size and date. Narrow the list with the Prefix box if the bucket is large.
  4. Choose the table to import into, tick the files you want, and select Import selected.

Files that cannot be imported — JSON, or anything over 200 MB — are shown greyed out with the reason. The target table must already exist, so create it with a metadata file first as described in 4.2.

4.5  Managing what you have connected

The connections table shows each source's type and whether it last connected successfully. Use the icons at the end of each row to re-test, edit or remove a connection. Removing a connection does not delete anything in the source system.

05Create an AI agent

An agent is a configured assistant pointed at a specific slice of your data. Most organisations run several — one per subject area — so that each gives focused answers rather than searching everything at once.

Open AI Agents and choose Create Agent.

5.1  Choosing what it can see

Data source
The agent queries a connected database directly, and can see every table in it.
Tables
The agent is limited to the specific uploaded tables you tick.
Documents
The agent answers from uploaded documents rather than tables.

Give the agent a clear name and a one-line description — these are what you will pick from later when asking a question.

5.2  Instructions

Each agent carries a set of instructions describing its role, its task and how it should phrase answers. You can write these yourself, or describe your business context in a sentence and use Generate prompts to draft them for you, then edit.

Good instructions are specific about tone, level of detail, and what the agent should do when it is unsure. It is worth revisiting them once you have seen a few real answers.

5.3  Business glossary

The glossary teaches an agent your organisation's vocabulary. If your teams say “enrolled” to mean something specific, define it once and every answer from that agent will use it consistently.

  1. Open the agent and go to its Glossary tab.
  2. Add a term, its definition, and optionally a category.
  3. For many terms at once, download the glossary template and use Bulk upload.
Worth the effort

The glossary is the single most effective way to improve answer quality. A dozen well-chosen definitions usually make more difference than lengthy instructions.

06Ask questions

Open Co-Pilot Query, choose an agent from the selector, and type your question as you would ask a colleague.

Questions that work well

  • How many sites enrolled patients last month?
  • Which regions are behind their targets, and by how much?
  • Show the ten most recent records, newest first.
  • Compare this quarter against the same quarter last year.

The answer comes back as prose rather than a raw table. Where an agent is querying a database, you can expand the answer to see the query it generated — useful if you want to verify the logic or hand it to an analyst.

Follow-up questions

Two or three suggested follow-ups appear under each answer. Selecting one asks it immediately. The conversation keeps its context, so you can also just say “and by region?” and be understood.

Rating an answer

The thumbs up and thumbs down beside each answer are not just feedback — they change future results. A rated answer, especially one with a written comment explaining what was wrong, is used as a worked example the next time a similar question is asked.

Getting better answers

If an answer misses, say why in the comment box rather than rephrasing and moving on. Two or three corrections on a common question noticeably improve the agent.

Working with documents

Agents pointed at documents answer from the text itself, quoting the relevant passages back in context. They work best for questions of interpretation — what a protocol requires, what a contract commits you to, what a report concluded.

You can ask questions in any language; the agent replies in the language you asked in, even where the underlying documents are written in another.

07Charts & graphs

Graph Query answers the same kind of question as Co-Pilot, but returns a chart instead of prose. Pick an agent, describe what you want to see, and a chart is built from the result.

Phrasing that produces good charts

  • Enrolments by month for the last year — a trend over time
  • Total by region — a comparison across categories
  • Top ten sites by volume — a ranking

Ask for something with a category and a number in it. Questions that return a single value, or a long list of unaggregated records, have nothing to plot.

Where a chart supports it, selecting a bar or segment drills into the detail behind it.

08Dashboards

A dashboard collects the questions you want to keep an eye on, so you do not have to ask them again each morning.

Creating one

  1. Open My Dashboards in the sidebar and choose New Dashboard.
  2. Give it a title, an optional description, and choose which agent it draws on.
  3. You are taken to the builder to add your first widget.

Adding widgets

  1. Choose Add Widget.
  2. Type the question the widget should answer.
  3. Pick how to present it — bar, line, pie, table, or a single summary figure.
  4. Name the widget so its purpose is clear at a glance, and save.

Widgets can be dragged into position and resized. The arrangement is saved with the dashboard, so everyone opening it sees the same layout.

Viewing and maintaining

Open a dashboard from My Dashboards, which lists yours with their widget count and when each was last changed. Widgets re-run their query when the dashboard is opened, so the figures are current.

Manage Dashboards is where you rename or delete them. Deleting a dashboard removes its widgets too; the underlying data is untouched.

Dashboards are personal

A dashboard is visible to the person who created it. Colleagues who need the same view should build their own, or you can share the underlying questions with them.

09Query log

Query Log is a record of every question asked in your organisation: who asked it, which agent answered, what came back, and how it was rated. Filter it by agent to focus on one subject area.

It is useful for three things:

  • Learning what to ask. New colleagues can see the questions that already work.
  • Spotting weak areas. A cluster of poor ratings against one agent points at instructions or glossary terms that need work.
  • Keeping a record. Every answer is retained with its query, so a figure quoted in a meeting can be traced back.

10Your organisation

Everyone signed in under the same organisation shares its connections, tables, documents and agents. Nothing is visible across organisations.

Inviting colleagues

Organisation admins only.

  1. Open Organisation Users from the sidebar.
  2. Choose Invite user and enter their email address and role.
  3. They receive an email with a temporary password and follow the steps in section 2.

Roles

Organisation admin
Everything below, plus inviting colleagues, changing roles and removing members.
Organisation user
Connect data, create agents, ask questions and build dashboards.

Members can be selected in bulk to change roles, resend invitations or remove several people at once.

Your own account

Profile holds your name, contact details and password, along with your usage for the current period.

11Troubleshooting

What you seeWhat to do
“Authentication failed” when testing a connection The username or password is wrong. Check for trailing spaces, and confirm the account has permission to read the database.
“Connection timed out” CliniOps reached the network but nothing answered. For AWS RDS check the security group; for Azure SQL add the server's IP to the firewall rules; otherwise confirm the port.
“Host not found” The server address is wrong or misspelled. For RDS, copy the endpoint from the AWS console without the port on the end.
“Access denied” when browsing S3 The key needs permission to list the bucket and read its contents. If the message mentions the region, set the region the bucket was created in.
“Schema mismatch” on upload The file's columns do not match the table's. The message lists both sets — compare them for renamed, extra or missing columns.
The agent says it has no documents The agent has no files attached, or they were removed. Open the agent and re-select its documents.
An answer looks wrong Rate it down and say what was wrong. Then check the glossary — a term being read differently than you intend is the usual cause.
An answer is vague or asks for clarification Add the missing specifics: a time period, a region, a metric. Agents ask rather than guess.
Signed out unexpectedly Sessions expire after a period of inactivity. Sign in again; you will be returned to the page you were on.
A chart comes back empty The question returned no rows, or nothing chartable. Rephrase so it asks for a number grouped by a category.

If a problem persists, note the exact wording of the message and the question you asked, and pass both to your CliniOps administrator.

12Glossary

Agent
A configured assistant pointed at a defined slice of your data, with its own instructions and glossary.
Business glossary
Your organisation's definitions of its own terms, so answers use your vocabulary consistently.
Connection
Saved details for reaching a database or storage bucket.
Dashboard
A saved arrangement of widgets, each answering one question.
Data source
Any origin of data: a connected database, uploaded spreadsheets, or documents.
Metadata file
A short spreadsheet describing a table's columns and what they mean. Required when creating a new table.
Organisation
Your company or team. All data and agents belong to one, and are never visible outside it.
Prefix
A folder path inside an S3 bucket, used to narrow what is listed.
Structured data
Data in rows and columns — spreadsheets and database tables.
Unstructured data
Written documents — PDFs, Word files, reports, notes.
Widget
One question saved onto a dashboard, shown as a chart, table or single figure.
